Riordanverse API: getting started

Build a character reference, lore browser, or other integration with structured JSON. The Riordanverse API is a read-only REST API whose current coverage focuses on Percy Jackson and related Greek and Roman stories, not every Riordanverse series. Lore endpoints support reading data, not creating or editing it.

Base URL: {{ api_base_url }}

Explore the resources

Browse characters, divinities, creatures, items, locations, organizations, and narrative resources such as books and quests. List endpoints return collections; detail endpoints use slugs to identify individual records. Consult the API directory and endpoint documentation for the available routes, fields, and relationships.

Rate limiting

To keep Riordanverse API available and prevent abuse, protected data requests are limited to 1,000 requests per hour per API key in a fixed one-hour window. Key revocation shares this quota.

Requesting an API key and verifying a key each have a separate limit of 5 requests per hour per client IP address.

When a limit is exceeded, the API returns 429 Too Many Requests. Wait for the duration indicated by the Retry-After response header before retrying. Responses that reach the API-key quota check include RateLimit-Limit, RateLimit-Remaining, and RateLimit-Reset; requests rejected before that check do not. Key-request and verification responses do not include these quota headers.

Public pages, the API directory, documentation, and health checks do not consume these quotas. Executing a protected data request through Swagger still consumes the API-key quota. If Redis is unavailable, quota counters fall back to process-local memory and are not shared across workers.

1. Request an API key

Send a JSON POST request to {{ request_key_url }} with your application's consumer_name and a valid email. No existing API key is needed to request one. Replace the example identity with your own. 

{{ guide_request_key_raw }}

A successful request returns HTTP 201 with api_key, consumer_name, email, and message. Save the api_key securely: its plaintext value is shown only once.

Protected data endpoints require the X-API-Key header on every request. Set API_KEY to your issued key in your shell before running these examples. Keys embedded in browser JavaScript or sent by a browser are public to its users; they cannot be kept secret in a client bundle. Keep confidential keys on your server and out of public repositories.

Verify your key

Send a POST request with the same header and no request body:

curl -X POST '{{ origin }}{% url 'verify-api-key' %}' \
  -H "X-API-Key: $API_KEY"

Verification returns HTTP 200 with valid and consumer_name. For an invalid or missing key, valid is false and consumer_name is null. Check valid, not just the HTTP status. Key requests and verification are each limited to five attempts per hour per IP; HTTP 429 indicates throttling.

2. Make a filtered request

{{ guide_request_raw }}

For example, append ?divine_parent=poseidon&is_demigod=true&sort=name&order=asc&page=1&limit=20 to the characters/ collection URL. The divine_parent filter accepts a god or titan slug, such as poseidon, and matches parent relationships. Boolean filters such as is_demigod accept only lowercase true or false.

Character lists accept sort=name, sort=status, or sort=age_first_appearance. Use order=asc or order=desc; the direction defaults to ascending when a sort field is given. Supply sort whenever you supply order. Other endpoints have their own supported filters and sort fields, listed in the docs.

3. Read the paginated response

Paginated lists contain a data array and a meta object with total, page, limit, and total_pages. The default page size is 20. Set limit to request another page size, up to a maximum of 100, and use page=2 for the next page. Keep the same filters and sorting as you move between pages. An empty filtered collection does not guarantee that a particular character or relationship is available.
